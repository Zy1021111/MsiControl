## 1. 能力等级制度

这是本项目「不显示虚假成功」原则的落地机制，对应任务书 §1 原则 4/6/11。

```csharp
public enum CapabilityLevel
{
    Verified,     // 已确证：有实机返回值或实测证据
    Detected,     // 线索：接口/方法/设备存在，语义未验证
    Unknown,      // 待验证：无证据
    Unsupported   // 不支持：已确认不可用
}
```

### 1.1 强制规则

| 等级 | 允许的界面行为 | 允许的代码行为 |
|---|---|---|
| `Verified` | 可开放读写 | 可调用写入方法 |
| `Detected` | **仅允许只读展示**，或明确标注为探测结果 | 只读调用；写入必须被禁用 |
| `Unknown` | **一律禁用**，给出原因文案 | 不得调用 |
| `Unsupported` | 显式禁用，说明已确认不可用及依据 | 不得引用 |

### 1.2 升级路径

任何能力从 `Detected` 升到 `Verified`，必须满足：

1. 有实机调用记录（命令 + 原始返回）。
2. 有读回值且读回值与请求一致，或说明了允许的偏差范围。
3. 证据写入 `docs/hardware-evidence.md`，标注日期与来源。

**仅凭「方法名存在」不得升级。**

## 2. 单位与口径约定

冷却后台最常见的错误来源是单位。**所有换算必须走 `MsiControl.Core.Measurement`，禁止各模块自行换算。**

| 量 | 内部单位 | 外部/界面单位 | 陷阱 |
|---|---|---|---|
| 温度 | `double`，摄氏度 | °C | ACPI 热区原始值为**十分之一开尔文**，须 `/10 - 273.15` |
| 频率 | `double`，MHz | GHz（界面除以 1000） | 曲线横轴单位为 °C，不要混用 |
| 功耗 | `decimal`，瓦 | W | 用 `decimal` 避免浮点累加误差 |
| 风扇转速 | `int`，RPM | RPM 或 % | 百分比必须由校准基准推导，不可反推 |
| 百分比 | `double`，0–100 | % | 与 RPM 是**两个不同量**，不可互换 |

### 2.1 整机功耗口径

任务书 §6.5 要求区分三种来源，模型中用独立枚举表达，**三者不可相加**：

| 口径 | 含义 |
|---|---|
| `BatterySide` | 电池放电功率 |
| `AdapterInput` | 适配器输入功率 |
| `WallSocket` | 插座侧功率 |

无可靠来源时必须返回 `Unavailable`，**不得用 CPU+GPU 功耗之和顶替**。

### 2.2 CPU 频率口径

只显示一个统一数值。约定为**所有活跃核心时钟的均值**（`AverageActive`），
并在界面注明统计口径。不显示基频，不拆分 P/E 核。

## 3. 状态枚举

### 3.1 读数状态

```csharp
public enum ReadingStatus
{
    Valid,
    Sleeping,
    Unavailable,
    Stale
}
```

**关键约束**：数据过期时必须置为 `Stale`，**不得沿用上一个有效值冒充当前读数**。

### 3.2 操作状态

```csharp
public enum OperationStatus
{
    Succeeded,
    PartiallySucceeded,
    Failed,
    PendingRestart,
    Unsupported
}
```

**关键约束**：

- `Succeeded` 必须有可追溯的确认依据（`SettingResult.ConfirmationBasis`）。
- `PendingRestart` 与 v1.1 的「待生效」是同一含义；**不得用于「不重启但需过渡」的情形**。
- 部分失败时**不得**宣称整组回滚成功；必须先读取实际状态。

## 5. 工程约定

| 项目 | 约定 |
|---|---|
| 目标框架 | 库 `net8.0`；Windows 项目 `net8.0-windows` |
| 平台专用层 | `MsiControl.Hardware.Msi` 因 `System.Management` 使用 **`net8.0-windows`**；消费方（含测试）须同 TFM。`MsiControl.Core` 保持 `net8.0` |

## 6. 异步与取消约定

- 所有硬件访问接口**一律异步**，并接受 `CancellationToken`。
- 接口实现**不得吞掉 `OperationCanceledException`**。
- **写入开始后，取消请求不能跳过必要的状态核对**（任务书 §16）。
  实现上意味着：`ApplyXxxAsync` 在收到取消时仍应完成读回，再抛出取消异常。

## 7. 禁止事项清单

以下行为在评审中直接判不通过：

1. 引用 `MSI_CPU` / `MSI_Power` / `MSI_VGA` / `MSI_Master_Battery` / `MSI_Slave_Battery`。
2. 把 `MSiSCSI_*` / `MSIde*` / `ISR_MSI` 当作能力证据。
3. 用 0、-1 或极大数字表达「原生上限」。
4. 用 CPU+GPU 功耗之和冒充整机功耗。
5. 用 Windows CPU 百分比冒充精确功耗限制，或用「禁用睿频」冒充睿频上限。
6. 数据过期后沿用上一有效值。
7. 未达到 `Verified` 就开放写入。
8. 用设备管理器禁用显卡冒充核显模式。
9. 未经用户配合执行风扇全速 / 重启类测试。
10. 交付时声称「应该可以编译」而不附真实构建输出。
