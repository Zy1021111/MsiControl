# MSI-Control 设计定稿

版本：v1.0
日期：2026-10-15
状态：待最终审批
项目类型：开源 Windows 笔记本控制台

## 1. 项目定位

MSI-Control 是以 G-Helper 的轻量、紧凑和直接操作方式为主要参考，
针对 MSI 笔记本开发的本地控制工具。

首要适配设备为 MSI Vector 16 HX AI A2XWHG / MS-15M3。

在实现完整功能和保证控制可靠性的前提下，尽量降低：

- 内存占用。
- CPU 占用。
- 安装与储存占用。
- 启动耗时。
- 不必要的独显唤醒。

不依赖云账号，不自动上传硬件数据，不提供自动更新检查。

## 2. 目标设备与兼容范围

### 2.1 首要设备

| 项目 | 信息 |
|---|---|
| 型号 | MSI Vector 16 HX AI A2XWHG |
| 主板 | MS-15M3 REV:1.0 |
| CPU | Intel Core Ultra 9 275HX |
| 独显 | NVIDIA GeForce RTX 5070 Ti Laptop GPU |
| 核显 | Intel Graphics |
| BIOS | E15M3IMS.117 |
| EC | 待读取有效版本；SMBIOS 的 255/255 不作为版本 |
| 操作系统 | Windows 11 专业版 x64，Build 26300 |
| 外接显示器 | 使用 DP 转雷电连接，具体显示拓扑需实机确认 |
| 现有控制工具 | Intel XTU、MSI Afterburner |

### 2.2 兼容原则

- 优先完成首要设备的完整适配和实机验证。
- 通用监控尽量兼容其他设备。
- 硬件控制采用可扩展适配器结构。
- 按功能判断能力，不把同品牌或同系列视为全功能支持。
- 未确认的设备与固件不开放未知硬件写入。
- 固件、驱动或接口发生变化时重新检查相关能力。
- WMI 类存在只作为线索，不视为控制功能已验证。

## 3. 功能范围

包含：

1. 实时硬件监控。
2. CPU/GPU 风扇曲线控制。
3. 强冷与风扇校准。
4. 五档可编辑性能模式。
5. CPU/GPU 功耗限制。
6. CPU 睿频上限。
7. 核显、混合、独显模式切换。
8. 正常窗口与迷你窗口。
9. 托盘、开机启动和快捷键。
10. 配置管理与本地诊断。

不包含：

- 电池保护与电池校准。
- 灯效。
- 屏幕校色。
- BIOS/EC 刷写。
- 游戏 FPS 叠加层。
- GPU 超频与 VF 曲线编辑。
- 云账号、遥测和在线反馈后台。
- 自动更新检查。

## 4. 界面总体设计

### 4.1 风格

- 借鉴 G-Helper 的紧凑工具布局。
- 简体中文。
- 跟随 Windows 明暗主题。
- 常用操作直接可见，详细设置按需展开。
- 不使用宽大侧边栏和多层导航。
- 不使用持续发光、复杂转场和高频动画。
- 支持系统 DPI 缩放与键盘操作。

### 4.2 正常窗口

默认打开正常窗口。

提供全部功能：

- 仪表盘。
- 性能模式。
- 显卡模式。
- 风扇控制。
- 精简设置与诊断。

风扇曲线和性能详细参数可使用展开区域或编辑窗口。
具体布局在界面设计阶段确定，不改变功能范围。

### 4.3 迷你窗口

包含：

- 五档性能模式快捷切换。
- 显卡模式切换。
- CPU/GPU 温度。
- CPU/GPU 频率。
- CPU/GPU 功耗。
- CPU/GPU 风扇百分比或 RPM。
- 有可靠数据时显示整机功耗。
- 返回正常窗口。

不包含强冷按钮。
不置顶。

### 4.4 窗口生命周期

- 两种窗口共用数据、采样和控制核心。
- 默认只显示一个窗口。
- 切换窗口不重复初始化硬件。
- 自动记住窗口位置和尺寸。
- 隐藏页面停止不必要的绘制。
- 点击关闭按钮进入托盘。
- 托盘提供完全退出入口。

## 5. 仪表盘

### 5.1 当前模式

显示实际生效的：

- 性能模式。
- 显卡模式。

目标设置尚未生效时，另行标注待生效状态。

### 5.2 CPU 核心监控

- 温度，°C。
- 频率，GHz。
- 风扇百分比 / RPM。
- CPU 封装功耗，W。

CPU 频率显示一个统一数值，注明统计口径。
不拆分 P 核与 E 核显示。

### 5.3 GPU 核心监控

默认监控 RTX 5070 Ti 独显：

- 温度，°C。
- 核心频率，GHz。
- 风扇百分比 / RPM。
- GPU 功耗，W。

### 5.4 整机功耗

- 独立展示整机功耗。
- 注明数据来源与测量口径。
- 不将 CPU 与 GPU 功耗之和标为整机功耗。
- 电池侧、适配器输入侧和插座侧数据明确区分。
- 没有可靠来源时显示“不可用”。

### 5.5 扩展传感器

按本机能力折叠展示：

- CPU/GPU 利用率。
- 显存占用与频率。
- 内存占用。
- SSD 温度。
- 可读取的功耗限制和温度限制状态。
- 其他经验证的传感器。

### 5.6 读数与刷新规则

- 默认每 1 秒刷新。
- 风扇默认显示百分比。
- 未完成有效校准时显示 RPM。
- 支持百分比 / RPM 切换。
- 实际转速百分比与曲线目标输出百分比明确区分。
- 独显休眠显示“休眠”。
- 读取失败显示“不可用”。
- 过期数据标记为过期。
- 不因监控持续唤醒独显。
- 数据来源与更新时间折叠展示。
- 不增加独立趋势图。

## 6. 性能模式

### 6.1 初始预设

| 模式 | CPU 目标上限 | GPU 目标上限 |
|---|---:|---:|
| 节能 | 10 W | 20 W |
| 安静 | 50 W | 80 W |
| 平衡 | 60 W | 90 W |
| 高性能 | 原生上限 | 原生上限 |
| 狂暴 | 原生上限 | 原生上限 |

数值是功耗限制目标，不是持续耗电目标。

原生上限表示取消 MSI-Control 的额外限制，
恢复本机支持的原生性能策略，不绕过硬件保护。

以上目标是否能精确应用，须实机验证。

### 6.2 每档独立配置

每个性能模式均支持独立保存：

- CPU 持续功耗上限。
- CPU 短时功耗上限。
- CPU 睿频上限。
- GPU 功耗上限。
- GPU 兼容节能策略。
- CPU 风扇曲线。
- GPU 风扇曲线。

同时协调：

- MSI 固件性能场景。
- Windows 电源策略。

CPU 睿频上限优先以频率单位表达。
具体可控范围和核心类型约束按接口能力确定。

### 6.3 CPU 限制

默认严格限制：

- 持续和短时功耗限制尽可能均受设定值约束。
- 不使用处理器百分比设置冒充精确瓦数限制。
- 不通过禁用睿频冒充可调的精确睿频上限。
- 明确报告不可写、被锁定或被固件覆盖的项目。

限制机制的时间窗口可能允许瞬时偏差，
不能承诺每次采样均低于设定值。

### 6.4 GPU 限制与替代策略

优先使用本机支持的功耗限制接口。

目标值不支持时：

- 报告实际支持范围。
- 不静默替换目标。
- 提供明确标注的兼容节能策略。
- 替代策略仅使用经过验证且属于当前功能范围的接口。
- 替代策略不保证精确达到目标瓦数。

### 6.5 高性能与狂暴

高性能：

- 使用原生性能预算。
- 使用独立可编辑的高性能风扇曲线。

狂暴：

- 使用本机经验证的最高原生性能场景。
- 使用独立可编辑的积极风扇曲线。
- 不自动开启强冷。
- 不预设本机支持 APEX / Surge。

若没有额外性能能力，明确说明两档主要由散热配置区分。

### 6.6 应用结果

逐项显示：

- 用户请求值。
- 接口操作结果。
- 可读回的实际限制。
- 当前实际功耗和频率。
- 成功、部分成功或失败。

低负载下实际功耗小于目标，不能单独证明限制生效。

## 7. 风扇控制

风扇控制为最高优先级模块。

### 7.1 模式

- 自动。
- 自定义曲线。
- 独立强冷开关。

每个性能模式拥有独立 CPU/GPU 曲线。

### 7.2 曲线编辑

支持：

- CPU/GPU 分别编辑。
- 温度节点滑块。
- 曲线图。
- 精确数值表。
- 编辑视图同步。
- 显示当前温度和实际转速。
- 百分比 / RPM 显示切换。

约束：

- 节点数量由固件决定。
- 温度阈值是否可编辑由接口决定。
- 输出范围与步长按实机验证设置。
- 物理风扇与 CPU/GPU 对应关系需确认。
- 不直接套用参考图片中的数值。
- 不承诺固件只能设置输出时可精确指定任意 RPM。

### 7.3 配置管理

支持：

- 保存。
- 重命名。
- 删除。
- 导入。
- 导出。
- 标签。
- 排序。

导入时检查格式与设备兼容性。
导入后显式应用，不自动写入。

次要操作收进菜单，保持界面紧凑。

### 7.4 状态与应用

明确区分：

- 编辑中的配置。
- 本地保存的配置。
- 最近成功应用的配置。
- 当前读取到的硬件状态。

规则：

- 显式应用才写入。
- 首次修改前保存有效快照。
- 写入后读回确认。
- 失败时显示实际状态和原因。
- 提供恢复快照与切回自动入口。

恢复启动曲线不等于 BIOS 出厂重置。

### 7.5 强冷

- 正常窗口、托盘和快捷键可控制。
- 迷你窗口不提供按钮。
- 进入前记录有效策略。
- 退出后恢复原策略并核对。
- 不与狂暴模式强制绑定。

### 7.6 校准

- 显示过程与结果。
- 支持取消。
- 保存有效 RPM 基准。
- 完成或取消后恢复原策略并核对。

满速校准不等于建立全部输出值到 RPM 的精确映射。

### 7.7 执行机制

优先让固件执行曲线。

如必须持续软件调速，则实现：

- 温度滞回。
- 升降速节流。
- 传感器超时处理。
- 睡眠唤醒处理。
- 异常保护。

恢复能力必须实机验证，不预先保证恢复一定成功。

## 8. 显卡模式

提供：

- 核显。
- 混合。
- 独显直连。

### 8.1 规则

- 与性能模式独立保存。
- 启动和供电变化时不自动切换显卡模式。
- 按本机能力开放。
- 显示当前模式与待生效模式。
- 明确重启或关机再开机要求。
- 支持稍后生效。
- 不自动重启。
- 生效后重新读取确认。

### 8.2 外接显示器

切换前确认：

- 雷电/USB-C 到显示器的实际连接路径。
- 外接显示器是否依赖独显。
- 目标模式是否会使外接屏断开。
- 是否存在接口限制。

不能仅根据线缆名称推断显示拓扑。

### 8.3 禁止替代

- 不用设备管理器禁用显卡冒充核显模式。
- 不用应用 GPU 偏好冒充 MUX 切换。
- 区分 MUX 与 Advanced Optimus。

## 9. 自动行为与退出

### 9.1 启动

- 开机启动默认开启，可关闭。
- 默认显示正常窗口。
- 恢复最近成功应用的性能与风扇配置。
- 显卡模式不自动切换。
- 校验设备与配置适用性后才恢复。

### 9.2 供电变化

拔掉电源：

- 记录原性能模式。
- 自动切换节能模式。

重新插电：

- 如未在拔电后手动更改模式，恢复拔电前模式。
- 如已手动更改，保留手动选择。

不自动切换显卡模式。

### 9.3 关闭与退出

关闭窗口：

- 进入托盘。
- 继续监控和控制。

完全退出：

- 目标是保留最后成功应用的硬件状态。
- 固件持久执行的设置可以在进程退出后继续生效。
- 依赖持续软件控制的设置，不能承诺在全部进程退出后维持。

若实测必须保留控制进程：

- 明确区分“退出界面、继续控制”和“停止全部进程”。
- 停止全部进程前，明确显示相关设置的实际退出行为。

## 10. XTU 与 Afterburner 共存

MSI-Control 接管：

- CPU 功耗。
- CPU 睿频上限。
- GPU 功耗。
- 风扇控制。

XTU 和 Afterburner 可以保留，但关闭重叠参数的自动应用。

实现要求：

- 检测可识别的冲突来源。
- 显示设置被其他程序覆盖的状态。
- 不通过无休止重写争夺控制。
- 不擅自修改或删除第三方软件配置。
- 不自动停止或卸载这些软件。
- 具体冲突来源可能需要用户配合确认。

## 11. 快捷键与托盘

全局快捷键：

- 显示/隐藏窗口。
- 强冷切换。

支持修改和关闭快捷键。
冲突时提示，不强制占用。

托盘提供：

- 打开正常窗口。
- 打开迷你窗口。
- 性能模式切换。
- 强冷切换。
- 退出。

## 12. 精简设置与诊断

仅保留三组。

### 12.1 启动与窗口

- 开机启动。
- 关闭到托盘。
- 正常 / 迷你窗口入口。
- 快捷键。

### 12.2 数据与配置

- 刷新间隔。
- 应用配置导入/导出。
- 恢复应用默认设置。

风扇和性能配置在对应编辑区域管理。

### 12.3 设备与诊断

- 硬件与固件信息。
- 功能支持状态。
- 导出本地日志。

日志导出避免包含不必要的序列号和个人路径信息。

## 13. 内部架构

### 13.1 方向

- 原生 Windows 桌面应用。
- 优先单一常驻进程。
- 不预设额外 Windows 服务。
- 不使用 Electron 或 WebView2 承载界面。
- 硬件访问与 UI 分离。
- 全部写入统一协调。
- 按需初始化传感器和编辑页面。

驱动或特权进程是否必要，必须由实际接口决定。

### 13.2 技术栈

优先验证 C# + WinForms。

使用 WPF 作为对照方案。

最终选择依据：

- 功能完整性。
- 内存与 CPU 实测。
- 发布体积。
- 曲线编辑体验。
- 系统主题和 DPI 支持。
- 硬件库集成成本。

具体 .NET 版本在实现时选择受支持版本。

不以技术偏好替代测量结论。

### 13.3 模块划分

```text
src/
├─ Contracts/       共享接口、模型和操作结果
├─ Monitoring/      统一采样和数据有效期
├─ FanControl/      曲线、校准、强冷和恢复
├─ Performance/     档位、功耗和 CPU 睿频限制
├─ Graphics/        显卡模式与待生效状态
├─ Hardware.Msi/    MSI 硬件访问与 MS-15M3 适配
├─ Configuration/   配置校验、保存和迁移
└─ Desktop/         正常窗口、迷你窗口和托盘
```

各模块分开编写、独立验证。

先确定接口，再逐步接入宿主。
不等所有模块完成才首次整合。
源码分模块不意味着发布时运行多个程序。

### 13.4 协调规则

- 区分请求状态与实际状态。
- 写入串行协调。
- 长操作不阻塞 UI。
- 操作有超时与明确结果。
- 最新用户操作优先。
- 启动恢复和供电变化不得覆盖更新的手动选择。
- 监控与控制共用适用的数据。
- 不周期性创建外部命令进程采样。

## 14. 资源与发布

### 14.1 原则

在完整功能前提下持续精简。

- 共享采样。
- 避免重复后台任务。
- 隐藏页面停止无用绘制。
- 扩展数据按需读取。
- 控制必需采样不因隐藏界面中断。
- 精简依赖、品牌适配和资源。
- 日志轮转并限制总量。
- 不无限保存监控历史。

### 14.2 发布形式

先提供功能完整的发布包，再根据测量继续精简。

“完整版”指功能和必要依赖完整，不强制要求单文件。

对比依赖运行时与自包含发布，记录：

- 下载包大小。
- 应用安装大小。
- 额外运行时大小。
- 必要驱动大小。
- 首次部署总量。

### 14.3 测量

分别测量：

- 正常窗口。
- 迷你窗口。
- 托盘待机。
- 风扇编辑。
- 校准过程。

记录：

- 内存。
- CPU。
- 启动耗时。
- 磁盘占用。

具体预算在首个可运行版本中建立基线，
不能在未验证前承诺固定 MB 数值。

## 16. 必须完成的技术调查

### 16.1 同类源码

核对 G-Helper 等项目的：

- UI 与硬件控制边界。
- 风扇和功耗应用流程。
- 配置保存方式。
- 休眠唤醒处理。
- 托盘和窗口生命周期。
- 退出后的状态。
- 依赖、权限与资源策略。
- 许可证。

### 16.2 本机能力

验证：

- 有效 EC 版本。
- 风扇读取、曲线格式和写入路径。
- 强冷接口。
- CPU 功耗与睿频上限。
- GPU 功耗范围。
- GPU 兼容节能策略。
- 显卡切换及外接屏约束。
- 整机功耗来源。
- 退出、重启和睡眠后的行为。
- 与 XTU、Afterburner 的实际冲突。

现阶段这些能力尚未全部确认。

无法实现的功能须说明原因与替代方案，
不得以虚假成功状态满足界面要求。

## 17. 开发顺序

1. 阅读已有接口输出并完成关键源码调查。
2. 建立本机能力与证据清单。
3. 确定共享接口和技术栈基线。
4. 建立轻量桌面宿主。
5. 分模块实现监控、风扇、性能和显卡控制。
6. 逐步整合正常窗口。
7. 完成迷你窗口、托盘和快捷键。
8. 验证启动、供电变化和睡眠唤醒。
9. 验证 XTU、Afterburner 共存。
10. 测量并优化资源。
11. 完成实机验收和开源发布准备。

## 18. 验收标准

- 监控真实，口径明确，实时刷新。
- 无效、过期和休眠状态准确。
- 整机功耗来源可信或明确不可用。
- 双风扇曲线可应用并确认结果。
- 强冷和校准恢复经过实测。
- 每档性能配置独立保存。
- CPU/GPU 限制及 CPU 睿频设置有明确结果。
- 不支持的目标与替代策略明确区分。
- 显卡模式与待生效状态准确。
- 两种窗口状态一致。
- 供电切换尊重用户最新操作。
- 退出行为与实际持续控制能力一致。
- 无无限重写、无限日志或重复采样。
- 资源占用有可复现测量。
- 开源代码与依赖许可证一致。
