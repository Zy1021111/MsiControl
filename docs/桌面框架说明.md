## 2. 窗口结构

### 2.1 组成

```text
Program.Main
  ├─ 单实例：Mutex "Local\MSI-Control.Desktop.SingleInstance"
  │            + EventWaitHandle "Local\MSI-Control.Desktop.Activate"（唤醒已有实例）
  └─ DesktopApplicationContext（宿主）
       ├─ MainForm        正常窗口（默认）
       ├─ MiniForm        迷你窗口
       ├─ SettingsForm    设置与诊断（按需创建）
       ├─ TrayHost        托盘图标与菜单
       ├─ HotkeyManager   全局快捷键（隐藏消息窗接收 WM_HOTKEY）
       ├─ SnapshotStream  唯一共享采样循环
       └─ ShellContext    数据路径 / 设置 / 日志 / 能力 / 采样 / 控制出口
```

### 2.2 正常窗口（`MainForm`）

自上而下：

1. 标题与设备标识（机型未识别时追加说明「机型未识别，全部写入入口按「待验证」禁用」）。
2. 顶部状态条：实际性能模式、实际显卡模式、整机功耗，以及**风扇显示切换**按钮。
3. CPU 四项：温度 / 频率 / 风扇 / 封装功耗。
4. GPU 四项：温度 / 核心频率 / 风扇 / 功耗。
5. 控制区：性能模式（5 档）、显卡模式（3 项）、风扇（自动 / 强冷 / 校准）。
6. **详细编辑（按需展开）**：风扇曲线状态行与编辑入口 + 性能详细参数配置目标表。
7. 扩展传感器（默认折叠）。
8. 操作结果行；底部状态栏为能力统计与数据来源/更新时间。

要点：

- 按用户要求（2026-10-18），主页面只保留核心内容：入口禁用原因不再铺陈在主页，
  完整清单见「设置与诊断」能力页；入口保留 `AccessibleDescription` 供屏幕阅读器读取。
- 待生效状态以附加信息出现，**不覆盖实际状态**（任务书 §6.1、§9.1）。
- 「详细编辑」默认收起，避免出现宽大侧边栏；展开后包含：
  - **风扇曲线**：当前生效控制模式状态行（EC 0xD4 读回）+ 曲线编辑器入口（属任务 04，未达 `Verified` 时禁用并说明）。
  - **性能详细参数**：五档 × （CPU 功耗 / CPU 睿频上限 / GPU 功耗上限）的配置目标表，行内编辑（回车生效、Esc 还原；CPU 功耗一个输入值同时作为持续与短时上限）。
    区段标题明确标注**这是本软件的配置目标，不是硬件读回值**，数值来源唯一
    （`PerformanceProfileCatalog`，界面层不另抄数字）。

### 2.3 迷你窗口（`MiniForm`）

五档性能切换、显卡模式切换、CPU/GPU 各四项、整机功耗、返回正常窗口、退出程序。

- `TopMost` **恒为 false**（不置顶），`MaximizeBox = false`。
- **不含强冷按钮**；窗口内以文字说明强冷的可用入口（正常窗口 / 托盘 / 快捷键）。
- 无记录位置时默认停靠到工作区右下角。

### 2.4 键盘操作与可访问性

| 能力 | 实现 |
|---|---|
| Tab 遍历 | 全部交互控件按视觉顺序设置 `TabIndex` |
| 助记键 | Alt+字母/数字：`&M` 迷你窗口、`&S` 设置、`&X` 退出、`&R` 风扇显示切换、`&T` 详细编辑、`&E` 扩展传感器、档位 `&1`–`&5`、显卡 `&I`/`&H`/`&D`、风扇 `&A`/`&F`/`&C` |
| 方向键 | 在档位按钮组与显卡按钮组内左右/上下循环移动焦点（`UiFactory.EnableArrowKeyNavigation`） |
| `Esc` | 按设置隐藏到托盘（不结束进程）；未启用托盘时给出提示 |
| `F5` | 立即用最近一次采样重绘 |
| 设置窗口 | `Enter` = 保存（`AcceptButton`），`Esc` = 关闭（`CancelButton`） |
| 屏幕阅读器 | 按钮设 `AccessibleName`（剔除 `&`）与 `AccessibleDescription`；自绘读数卡片在 `SetValue` 时同步 `AccessibleName`/`AccessibleDescription` |

不使用持续发光、复杂转场与高频动画（design.md §4.1）。

### 2.5 主题与 DPI

- 主题来源：`HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme`。
- 变化监听：`SystemEvents.UserPreferenceChanged`，封送到 UI 线程后比对**是否真的变化**再重绘
  （该事件会因多种系统设置触发）。
- 深色标题栏：`DwmSetWindowAttribute`（属性 20，回退 19）；无 `dwmapi` 时静默跳过。
- 调色板：`ThemePalette.Light` / `ThemePalette.Dark`。
- DPI：`Application.SetHighDpiMode(HighDpiMode.PerMonitorV2)` + 各窗体 `AutoScaleMode.Dpi`。
  **`app.manifest` 中刻意不再声明 `dpiAware` / `dpiAwareness`**——两处同时声明会触发 `WFAC010` 警告。
- 字体基准为 `UiFactory.BaseFont`（`SystemFonts.MessageBoxFont`，按系统 DPI 度量；取不到时回退
  `Control.DefaultFont`），子控件继承后随系统缩放。自绘卡片在换肤时按继承到的字体重算字号。
  次要文本只用颜色区分、不缩小字号，以免破坏字体继承。

### 2.6 生命周期与退出语义

| 行为 | 实现 |
|---|---|
| 两种窗口共用数据与控制核心 | 共享同一 `ShellContext`；切换窗口不重复初始化硬件 |
| 默认只显示一个窗口 | `ShowWindow` 先隐藏另一个窗体，并在显示后立即用最近一次采样渲染 |
| 关闭按钮 / `Esc` → 托盘 | 若 `CloseToTray` 为真则取消关闭并 `Hide()`，采样与控制继续 |
| 完全退出 | 托盘「退出（停止全部进程）」或窗口「退出程序」→ **先弹确认框**说明退出后果与「关闭到托盘」的区别，确认后才 `ExitApplication()` |
| 关闭按钮且未启用托盘 | 先 `e.Cancel = true` 再请求退出；用户在确认框选择「否」时窗体保持存活（否则会留下「窗口已销毁、进程仍在托盘」的残状态） |
| 不以隐藏进程冒充完全退出 | 退出路径写入日志：「退出后仅保留固件可持久执行的设置；依赖持续进程的软件调速不会继续生效」 |
| 隐藏时停止绘制 | 两窗体的采样回调在 `!Visible` 时直接返回，不更新文本 |
| 记住窗口位置 | 隐藏/退出时写回 `AppSettings`；多显示器变化时用 `WindowPlacement.ClampTo` 保证窗口仍可抓取 |
| 事件解绑 | 窗体 `Dispose` 时解除 `Snapshots.Updated` 订阅，避免已释放窗体被采样回调长期持有 |

## 3. 托盘与快捷键

- 托盘菜单：打开正常窗口 / 打开迷你窗口 / 性能模式（5 项）/ 强冷 / 退出。
- **`ContextMenuStrip.ShowItemToolTips = true`**：默认值为 `false`，不打开则禁用项的原因提示永远不显示，
  界面会退化成「只把入口变灰而不解释」。此外，禁用的项**在标题中直接写出原因摘要**
  （完整原因仍在工具提示中），因为并非所有系统设置都会显示菜单工具提示。
- 快捷键：显示/隐藏窗口（默认 `Ctrl+Alt+M`）、强冷切换（默认**关闭**）。
- 注册失败（含被其他程序占用，Win32 1409）不抛异常，而是产生一条报告 + 托盘气泡提示，
  程序继续运行——「冲突时提示，不强制占用」（任务书 §10）。
- **仅在绑定真正变化时才重注册**：无谓的重注册会短暂释放组合键，若期间被其他程序占用就会永久丢失
  （例如仅仅切换「风扇显示：百分比/RPM」也不应触碰全局快捷键）。

## 4. 配置存储

### 4.1 位置

```text
%LOCALAPPDATA%\MSI-Control\
├─ settings.json              设置（带版本信封）
├─ settings.bak.json          上一个可用版本
├─ corrupt-<时间戳>-settings.json   隔离的损坏/过新文件
├─ profiles\                  导入的配置档副本
└─ logs\
   ├─ msi-control.log         当前日志
   └─ msi-control.1..N.log    轮转历史（编号越大越旧）
```

不写系统级位置，不使用漫游目录，**不收集设备序列号**。

### 4.2 格式

```json
{
  "schemaVersion": 1,
  "savedAt": "2026-10-16T19:26:53.42+08:00",
  "settings": {
    "schemaVersion": 1,
    "launchOnStartup": true,
    "closeToTray": true,
    "startupWindow": 0,
    "refreshIntervalSeconds": 1,
    "fanDisplay": 0,
    "showHideWindowHotkey": {
      "enabled": true, "control": true, "alt": true, "shift": false, "windows": false, "keyName": "M"
    },
    "fullSpeedHotkey": {
      "enabled": false, "control": false, "alt": false, "shift": false, "windows": false, "keyName": "F"
    },
    "normalWindowPlacement": null,
    "miniWindowPlacement": null
  }
}
```

- `schemaVersion` 只出现在信封层，便于在字段结构变化时仍能稳定读取版本。
- 枚举以整数存储；键名为驼峰式；中文不转义（便于人工查看与手改）。
- **派生只读属性一律不写盘**（`[JsonIgnore]` 标注 `HotkeyBinding.HasModifier`/`IsComplete`、
  `WindowPlacement.IsUsable`）：写进去会让人以为「手工改它就能生效」，而它实际由其他字段推导。
  已有回归测试断言文件中不出现这些名字。
- 读取时允许注释与尾随逗号（`ReadCommentHandling.Skip`、`AllowTrailingCommas`）。

### 4.3 写入策略

1. 先写 `settings.json.tmp`；
2. 把现有 `settings.json` 复制为 `settings.bak.json`（失败不阻断保存）；
3. `File.Move(tmp, path, overwrite: true)` 原子替换。

避免断电或崩溃导致配置被截断。

**首次运行（或原文件已损坏/过新被隔离）时立即落盘一份默认设置**，
使配置文件的路径与格式对用户可见、可手工编辑，避免出现「设置界面有值、磁盘上没有文件」的状态。
写入失败只记录日志，不阻断启动。

### 4.4 迁移与容错策略

| 情形 | 行为 | 结果来源 |
|---|---|---|
| 文件不存在 | 使用默认设置，并立即落盘 | `Defaults` |
| 内容为空 | 使用默认设置，原文件保留 | `Defaults` |
| 解析失败 / 缺少 `settings` 节点 / 根节点非对象 | 隔离原文件为 `corrupt-<时间戳>-…`，回退默认并落盘 | `RecoveredFromCorrupt` |
| `schemaVersion` **高于**本程序支持 | 隔离原文件，回退默认（不尝试「尽力解析」） | `RecoveredFromUnsupportedVersion` |
| **无** `schemaVersion`（旧格式整份即设置对象） | 按当前版本解释并记录说明，下次保存补全信封 | `File` |
| `schemaVersion` **低于**当前版本 | 沿 `SettingsMigrator` 升级；**缺少中间步骤时拒绝升级并隔离** | `File` / 隔离 |
| 值越界或枚举非法 | 由 `AppSettings.Normalize()` 修正并记录说明 | `File` |

- 迁移表 `SettingsMigrator.DefaultSteps` **当前为空**：v1 是本项目首个设置版本，
  不存在需要修补的历史结构，不虚构历史版本。机制已就位，版本递增时在此登记步骤并补测试。
- `Normalize()` 每次加载都会执行（防御手工编辑与旧文件），修正项：
  刷新间隔越界、`startupWindow` / `fanDisplay` 枚举非法、快捷键不完整（关闭该快捷键）、窗口尺寸过小（丢弃）。

### 4.5 配置档（导入 / 导出 / 本地列表）

- 领域类型 `ConfigProfile` 必须带 `DeviceIdentity`。
  **说明**：任务要求「配置内必须记录 `DeviceIdentity`」，落实在**可导入导出的配置档**上
  （`ConfigProfile.Device`）；`settings.json` 是应用偏好（窗口/快捷键等），不含机型，
  因此换机导入设置不会被机型误拦——需要机型校验的是配置档，不是偏好。
- 序列化走独立的 DTO 形状；**重建必须经 Core 的工厂方法**
  （`PowerLimit.TryCustom` / `CpuTurboLimit.TryCustom` / `FanCurve.TryCreate`），
  否则会在导入路径上绕过「禁止用 0 表示无限」「短时不得低于持续」等不变量。
- 导入校验（`ConfigImportValidator`）：
  1. 配置版本不得高于本程序支持；
  2. **本机已识别**（`IsIdentified`）；
  3. **配置已记录有效机型**；
  4. **双方主板码一致**（`IsSameBoardAs`）——未识别 ≠ 同机型；
  5. 至少含一个档位且各档位 `Validate()` 为空。
- 通过校验后写入 `profiles\imported-<时间戳>.json`，并在界面与日志中返回固定说明：
  「导入后必须在界面显式应用才会写入硬件；本次导入未改动任何硬件设置」。
- 「设置与诊断 → 本地配置档」提供列表、刷新与**删除**（仅删除本软件保存在配置目录内的副本）。
  保存/重命名/标签/排序在风扇与性能编辑区域管理（任务 04/05）。

## 5. 日志

- 有界轮转：单文件 256 KiB × 保留 4 份 = **总量硬上限 1 MiB**，超出即删除最旧一份。
- **写入时脱敏**（不是导出时）：用户目录路径替换为 `%USERPROFILE%`（含 `Documents and Settings` 旧形式），
  `serial / serialNumber / 序列号 / sn` 形式的赋值替换为 `***`。
- 导出：合并全部轮转文件（从旧到新），并附加说明「日志在写入时已完成脱敏，不含设备序列号与用户目录路径」。
- 写入失败被吞掉且不递归记录日志——日志问题不得影响主流程。

## 6. 开机启动

任务书 §11 规定「开机启动默认开启，可关闭」。若只把开关画在界面上而不落实注册，
设置与真实行为就不一致，属于「显示与实际不符」。因此：

1. **启动时对账**：设置与注册表实际状态不一致时按设置修正，并把结果写入日志。
2. **仅在以自身可执行文件运行时才碰注册表**。开发主机（`dotnet.exe`）或测试宿主下只记录日志
   「当前以开发主机运行，未对开机启动项做任何读写」，避免留下指向 `dotnet.exe` 的无效启动项。
3. 只写**当前用户** `Run` 项，不写系统级 `Run`，不请求管理员权限，不创建计划任务或服务。
4. 设置界面同时显示**设置意图**与**注册表实际状态**（`StartupRegistration.IsEnabled()`），
   两者不一致时明确提示。
5. 环境不可写时，保存**不会**把已有的 `true` 改写成 `false`——环境限制不得覆盖用户意图。

## 7. 未适配入口清单及原因文案

界面默认运行（未注入设备标识与能力基线）时，设备为 `DeviceIdentity.Unknown`、能力集合为空，
**全部入口按 `Unknown` 禁用**，原因文案形如：

> 待验证：本机尚无该能力的证据，按未知处理并禁用。依据：未登记该能力，按未知处理。

当整合负责人（07）注入 MS-15M3 能力基线后，按下表呈现。
「入口状态」中的**写入**类入口一律禁用——这是 `Detected` 等级的强制规则（任务书 §16.1）。

| 界面入口 | 能力键 | MS-15M3 等级 | 入口状态 | 原因文案（要点） |
|---|---|---|---|---|
| 性能模式切换（5 档，窗口与托盘） | `firmware.scenario` | `Detected` | 禁用 | 线索：接口或方法存在，但语义与可用性尚未验证，因此仅允许只读展示，写入已禁用。依据：`Get_Device`/`Set_Device`、`Get_AP`/`Set_AP` 存在 |
| 显卡模式切换（3 项，窗口与托盘） | `graphics.mode` | `Unknown` | 禁用 | 待验证：本机尚无该能力的证据，按未知处理并禁用。依据：无候选接口 |
| 风扇：自动 / 自定义曲线 | `fan.curve` | `Detected` | 禁用 | 线索……依据：`Get_Fan`/`Set_Fan` 存在，未调用验证 |
| 风扇：曲线编辑器入口 | `fan.curve` | `Detected` | 禁用 | 同上一行 |
| 风扇：强冷（窗口、托盘、快捷键） | `fan.fullspeed` | `Unknown` | 禁用 | 待验证……依据：接口未定位 |
| 风扇：校准 | `fan.calibration` | `Unknown` | 禁用 | 待验证……依据：校准基准来源未定位 |
