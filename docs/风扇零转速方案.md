# 风扇 PWM 完全控制方案（PawnIO 路线）

> 目标：用 PawnIO 直接写 EC 的 PWM 占空比寄存器，把风扇转速设到指定值——包括尝试 0% 完全停转。
> 本文说明原理、接口、前提、控制逻辑、验证方法与回滚机制；结论部分如实记录本机实测边界。
>
> 实现：`src/MsiControl.Tools.EcExperiment/FanZeroController.cs` +
> `MsiControl.Tools.EcExperiment fanzero <probe|hold|zero>`。
> 本机证据：`docs/hardware-evidence.md` §23、§33、§36。

---

## 1. PawnIO 在这里到底做了什么

PawnIO 是「通用的用户态 I/O 驱动 + 可加载的 Pawn 脚本模块」。它的价值在于：
**把「需要内核权限的端口读写」收敛成一条受控的 IOCTL 通道**，而具体做什么由模块脚本定义，
模块源码公开、二进制可校验。

对本机风扇控制，链路只有一条：

```
用户态 FanZeroController
   │  DeviceIoControl(IoctlExecute, "ioctl_pio_read"/"ioctl_pio_write", cells)
   ▼
PawnIO 内核驱动（官方签名，按需启动）
   │  运行 LpcACPIEC 模块
   ▼
LPC I/O 端口 0x66（状态）/ 0x62（数据）   ← 端口白名单由模块强制
   ▼
EC 芯片：0x71（CPU 占空比）/ 0x89（GPU 占空比）
```

### 1.1 模块：`LpcACPIEC`

源码（`PawnIO.Modules/LpcACPIEC.p`）只导出两个函数：

| 函数 | 输入 cell | 输出 cell | 端口限制 |
|---|---|---|---|
| `ioctl_pio_read` | `[0]=port` | `[0]=value` | 仅 `0x62`、`0x66` |
| `ioctl_pio_write` | `[0]=port, [1]=value` | 无 | 仅 `0x62`、`0x66` |

- 模块**不提供** EC 内存读写，也**不提供**任何「关闭固件风扇控制」的开关。
- 源码注释明确要求：调用前应持有 `\BaseNamedObjects\Access_EC` mutant（本机该对象不存在，
  项目已实现「存在则等待、不存在则降级为进程内串行」并在诊断中如实标注）。
- 模块许可证 LGPL-2.1；本项目把 `.bin` 作为嵌入资源分发，加载前做 SHA-256 比对。

### 1.2 ACPI EC 事务（由用户态实现，不在模块里）

标准 ACPI EC 协议，命令口 `0x66`、数据口 `0x62`：

- 读：等 `IBF=0` → 写 `0x80`(RD_EC) → 等 `IBF=0` → 写寄存器地址 → 等 `OBF=1` → 读 `0x62`。
- 写：等 `IBF=0` → 写 `0x81`(WR_EC) → 等 `IBF=0` → 写地址 → 等 `IBF=0` → 写值。

状态位：`OBF = bit0`、`IBF = bit1`；每阶段超时 50 ms，前 0.2 ms 自旋。
实现见 `Transport/PawnIo/MsiEcPort.cs`。

### 1.3 驱动接口常量

| 项 | 值 |
|---|---|
| 设备路径 | `\\.\GlobalRoot\Device\PawnIO` |
| 加载模块 | `IOCTL = (41394 << 16) \| (0x821 << 2)`，输入为模块全部字节 |
| 执行方法 | `IOCTL = (41394 << 16) \| (0x841 << 2)`，输入 = 32 字节 ASCII 方法名 + 8 字节对齐的 long cell |

## 3. 控制逻辑

### 3.1 状态机

```
Idle ──CaptureBaseline──> Armed ──EnterManual(0xD4=0x8D, 读回校验)──> Running
  ▲                                                                    │
  └──────────────── Restore(写回基线 + 0xD4) ◄── 正常退出 / 异常 / 看门狗 ┘
```

### 3.2 每拍动作（周期 T，默认 100 ms）

```
读温度 0x68 / 0x80 → 看门狗判定（≥88 °C 立即停）
→ 写 0x71 = 目标, 读回核对
→ 写 0x89 = 目标, 读回核对
→ 累计「读回 == 目标」的保持率
```

保持率是本方案的核心指标：**写入成功不等于生效**，只有读回一致才算这一拍被固件接受。

### 3.3 为什么必须周期写，且周期要短

实测固件回写周期：CPU ≤1 s、GPU ≤100 ms（HWE §23.3、§36.4）。
因此维持非固件值时，写入周期必须显著短于回写周期：

| 周期 | CPU 通道 | GPU 通道 |
|---|---|---|
| 1000 ms | 大部分时间被回写 | 基本无效 |
| 100 ms | 可用 | 边缘（与回写同量级） |
| 50 ms | 可用 | 可压住但 EC 负载升高 |

代价：EC 事务频繁，单读瞬时超时率约 20%，必须带重试（本实现 3 次 × 20 ms）。

### 3.4 命令

```bash
# 预检（只读 + 污染探测）
MsiControl.Tools.EcExperiment.exe fanzero probe

# 保持指定占空比，统计保持率，退出自动回滚
MsiControl.Tools.EcExperiment.exe fanzero hold 45 20

# 停转协议（危险，必须显式开关）
MsiControl.Tools.EcExperiment.exe fanzero zero 8 --allow-zero
```

## 4. 转速读取与验证

**本机不存在可读的转速通道**：EC 寄存器表没有 RPM 项，NVML 对笔记本 GPU 的
`fan.speed` 恒为 `[N/A]`（HWE §12）。因此「验证」只能分三层，强度依次递增：

| 层级 | 手段 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| L1 寄存器 | 写后读回 + 保持率（本实现） | 固件是否接受并维持该值 | 物理转速 |
| L2 温升差分 | 相同负载下对比「目标值」与「已知值」的升温斜率 | 散热是否显著减弱 | 精确 RPM |
| L3 外部仪器 | 转速计 / 声级计 / 风量计 | 真实 RPM | — |

**结论口径**：只有 L1 通过时，只能说「占空比寄存器被维持」，不能说「风扇转到了 X 转」；
要宣称「已停转」必须 L2（温度不升）或 L3 支撑。

本项目界面上的 RPM 是**两点折线估算**（45% = 3000、100% = 9000，HWE §33），
不是测量值，这一点在来源字符串里如实标注。

## 5. 0% 停转的边界情况（本机实测）

| 边界 | 实测结果 | 影响 |
|---|---|---|
| 写 0 是否被接受 | 立即读回 0，CPU 侧 6 秒 55/55 帧保持 | 寄存器层面"成功" |
| 物理是否停转 | **否**：8 进程满载 30 秒，CPU 温度恒定 61 °C | 0% ≠ 停转 |
| GPU 通道 | 写 0 后 **100 ms** 即被回写 24% | GPU 侧 0% 无法维持 |
| 副作用 | 写 0 后固件进入持续回写 0 状态，写 20/60/100% 均在 ≤2 s 内被覆盖 | 软件无法用写入恢复 |
| 恢复 | 切 silent/auto、切性能档、强冷窗口压写、30 秒高频压写、**系统重启**全部无效（09:51 冷启动后仍为 0）；需 BIOS 加载默认设置或完全断电放电 | 持久化故障，代价最高 |
| 低占空比死区 | <20% 只点动不成转（HWE §24.1） | 1–19% 应抬到 20% |

**因此本方案对 0% 的处理是：默认拒绝。**

`fanzero zero` 不带 `--allow-zero` 直接返回码 3 并打印风险；带了开关也要先通过污染探测，
否则返回码 1 中止。这不是保守，而是因为「写 0 会污染固件状态」是可复现的事实。

### 5.1 如果换一台机器，要满足什么才能真的停转

1. EC 有独立 fan-off 位（或固件把 0 解释为停转指令）；
2. 写 0 能维持 ≥3 个固件回写周期；
3. 有转速计或温升证据可自证。

三条同时成立才可宣称停转。本机第 1、2 条即失败。

## 6. 安全性与回滚

| 机制 | 实现 |
|---|---|
| 写白名单 | 仅 0xD4 / 0x98 / 0xD2 / 0x71 / 0x89 / 0x2E / 0xD1，其余在协议层被拒 |
| 基线快照 | 进入手动模式前记录 `0xD4`、`0x71`、`0x89` 原值 |
| 退出回滚 | `finally` + `Dispose` 双路径写回基线，`0xD4` 交还 auto |
| 看门狗 | CPU/GPU 温度 ≥88 °C 立即停止写入并回滚；**回滚路径绕过看门狗**，避免安全机制反过来阻塞恢复 |
| 污染闸门 | 探测到「写非 0 被回写为 0」时，`hold`/`zero` 一律中止 |
| 显式开关 | 写 0 必须 `--allow-zero`，默认拒绝 |
| 事务容错 | 单读 3 次退避重试；写失败不重试（避免与固件争抢放大） |

## 7. 本机结论

1. **通道成立**：PawnIO + `LpcACPIEC` 可以稳定读写 0x71/0x89，读回一致。
2. **非零目标可控**（正常状态下的历史实测）：45% 写入后引擎可维持；GPU 通道受 100 ms 回写限制，
   需要更短周期才能压住。
3. **0% 完全停转不成立**：寄存器能写 0，但风扇物理不停转，且会触发固件回写 0 的状态污染。
4. **污染是持久的**：重启不清除，只能 BIOS 默认或断电放电。
5. **产品侧正确做法**：曲线目标 0% 时「交还固件」（`ReleasedToFirmware`），不写 0。

### 7.1 未完成的验证（受阻于污染状态）

`fanzero hold 45 20` / `hold 20 15` 尚未取得实测保持率：两次尝试都被污染闸门拦下
（§36.4 的持久锁定）。闸门本身行为正确——这是设计意图，不是缺陷。

