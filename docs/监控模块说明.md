## 2. 架构与单一采样约定

- 监控模块**不创建任何计时器或线程**。采样节奏由桌面壳的 `SnapshotStream`（任务 02）持有，
  每被调用一次就完整读一轮。因此「整个应用只有一个采样循环」由壳层保证，本模块天然不违反。
- 采样循环的调用链：`SnapshotStream` → `IMonitoringProvider.ReadAsync(ct)` → 依次询问各数据源。
- 数据源按功能抽象（`ICpuTemperatureSource` / `ICpuFrequencySource` / `ICpuPowerSource` /
  `IFanSpeedSource` / `IGpuSource` / `ISystemPowerSource` / `IExtendedSensorSource`），
  便于任务 07 用测试替身替换，也便于将来加入 LibreHardwareMonitor / NVML 之外的来源。

## 4. 读数口径说明

1. **CPU 温度**：ACPI 热区是唯一 `Verified` 温度源，但它是「ACPI 热区」而非 CPU 封装温度。
   来源字符串已写「（ACPI 热区，非 CPU 封装温度）」，界面应原样展示。
2. **CPU 频率**：`AverageActive`——活跃核心（`% Processor Time ≥ 1`）有效频率均值；
   整机接近空闲时退化为全部核心均值，来源字符串会注明。内部 MHz，界面除以 1000 显示 GHz。
3. **GPU 核心频率**：NVML 核心时钟，内部 MHz。
4. **风扇**：`Rpm` / `ActualPercent` / `TargetPercent` 三个字段互不替代。
   未校准时 `ActualPercent` 恒 `null`，界面回落显示 RPM；本机 RPM 与百分比均无验证来源，故为「不可用」。
5. **整机功耗**：口径分 `BatterySide` / `AdapterInput` / `WallSocket`，三者不可混用、不可相加；
   **绝不用 CPU+GPU 功耗之和顶替**。本机 `power.system` 为 `Unknown` → 恒「不可用」。
6. **扩展传感器**：按能力折叠展示；带刷新间隔的条目显示名会追加「（每 N 秒刷新）」。

## 5. 降级策略（哪些量不可用时代价是什么）

| 情形 | 行为 | 代价 |
|---|---|---|
| 数据源读取失败/异常 | 该槽位 `Unavailable`，记录原因 | 单槽位缺失，其余不受影响 |
| 数据源连续失败 ≥ 3 次 | 进入 30 秒退避，期间不再调用 | 避免线程堆积与反复重试 |
| 单个数据源超时（默认 2 s） | 该读数 `Unavailable` | 单槽位缺失；不阻塞采样周期 |
| 独显断电（PnP `Availability` 判定） | 整份 GPU 快照 `Sleeping`，显示「休眠」 | 不触碰 NVML，避免轮询唤醒独显 |
| 独显存在但读取失败 | `Unavailable`（与「休眠」区分） | 如实显示故障 |
| 采样整体超时 | 由 `SnapshotStream` 调 `MarkStale` | 有效读数转过期，绝不沿用旧值 |
| PDH 计数器不存在/初始化失败 | CPU 频率/利用率 `Unavailable` | 单槽位缺失 |
| NVML `nvml.dll` 缺失 | 独显四项 + 相关扩展 `Unavailable` | 独显监控整体不可用 |
| 能力键 `Unknown`/`Unsupported` | 不调用该数据源，给出禁用原因 | 符合 §16.1 能力门控 |

## 6. 资源占用实测

环境：本机 MS-15M3，Windows 11 Build 26300，CLR 8.0.32，测试宿主进程内 20 次 @1 s。

| 指标 | 值 |
|---|---|
| 单次采样耗时 | 平均约 17 ms，最大约 81 ms（首周期含 NVML 初始化与首次 WMI 连接） |
| 处理器性能计数（PDH） | 频率 0.6 ms / 利用率 0.2 ms |
| ACPI 热区 | 约 3 ms |
| 电池侧（BatteryStatus） | 约 1.5 ms |
| 内存（Win32_OperatingSystem） | 约 3 ms |
| 独显在线性探测（5 秒节流） | 约 15 ms |
| NVML 四项 + 扩展项 | 约 3 ms + 0.1 ms |
| EC 固件响应（仅一次） | 约 18 ms |
| 进程工作集 / 私有内存 | 约 85→90 MiB / 41 MiB |

> 「正常窗口 / 隐藏窗口」两态的差异属于 UI 绘制与窗体消息开销，不在监控层。
> 监控层只由单一采样循环驱动，与窗口可见性无关；完整程序的两态资源测量应由任务 07
> 在装配后统一进行（`RealHardwareTests` 已提供可复用的测量骨架）。

## 7. 接入方式（给任务 07）

```csharp
// 07 装配时：
var device     = /* Discovery 得到的 DeviceIdentity */;
var capabilities = CapabilityBaseline.ForDevice(device);
var monitoring = MonitoringProviderFactory.CreateDefault(capabilities, monitoringOptions: null);

// 传给 ShellContextFactory：
ShellContextFactory.CreateDefault(
    device: device,
    capabilities: capabilities,
    monitoringProvider: monitoring,
    controlSink: /* 07 的协调器 */);
```

要点：

- `MonitoringProvider` 实现 `IDisposable`，宿主退出时应 `Dispose()` 以释放 NVML 会话
  （不释放也不会泄漏增长，NVML 随进程退出由驱动回收）。
- 若需要诊断展示：`new MonitoringOptions { EnableDiagnostics = true }`，会在快照里附加
  `diag.*` 扩展传感器；`provider.Diagnostics` 提供各数据源的来源、最近成功时刻与失败原因。
- `provider.EcFirmware` 提供 `Get_EC` 的原始文本与十六进制，可填入「设备与诊断」页；
  是否据此回填 `DeviceIdentity.EcVersion` 由任务 01/07 决定（字段未拆分，见 §14.2）。
- 建议任务 01 复核 `power.system` 能力键：现已探明电池侧功率可读，可考虑仅限 `BatterySide`
  口径将其升为 `Verified`；升格后 `ReadSystemPowerAsync` 无需改代码即可生效。

## 9. 可选数据源：MSI Afterburner 共享内存（MAHM）

> **本节于 2026-10-17 追加**，对应叶哥「改用 Afterburner 获取监控数据」的明确决定。
> 该数据源为**可插拔的替代来源**，默认关闭；启用方式见 §9.3。

### 9.1 接入方式（技术机制）

- Afterburner 通过 Windows 命名文件映射对象 **`MAHMSharedMemory`** 暴露 GPU 监控读数。
  本项目新增 `src/MsiControl.Monitoring/Afterburner/`：
  - `MahmStructures.cs`：按官方 SDK 头文件 `MAHMSharedMemory.h`（Unwinder，guru3D）定义的
    `MAHM_SHARED_MEMORY_HEADER` 与 `MAHM_SHARED_MEMORY_ENTRY` 结构体，以及 `MONITORING_SOURCE_ID_*` 常量。
  - `MahmReader.cs`：`OpenFileMapping` + `MapViewOfFile` 进程内读取；做签名（`0xDEAD`）与条目大小校验。
  - `Sources/AfterburnerGpuSource.cs`：实现 `IGpuSource` + `IExtendedSensorSource`，
    把 MAHM 条目映射到 `GpuSnapshot` 与扩展传感器。

- **映射关系**（MAHM `data` 字段 → 模型字段）：

| Afterburner 数据源 | `MONITORING_SOURCE_ID` | 映射到 |
|---|---|---|
| GPU 温度 | `GPU_TEMPERATURE` (0x00) | `GpuSnapshot.Temperature` |
| 核心频率 | `CORE_CLOCK` (0x20) | `GpuSnapshot.CoreFrequencyMhz` |
| 显存频率 | `MEMORY_CLOCK` (0x22) | 扩展 `gpu.memclock` |
| GPU 利用率 | `GPU_USAGE` (0x30) | 扩展 `gpu.utilization` |
| 显存占用 | `MEMORY_USAGE` (0x31) | 扩展 `gpu.vram` |
| 风扇 RPM | `FAN_TACHOMETER` (0x11) | `GpuSnapshot.Fan.Rpm` / 扩展 `gpu.fan` |
| 风扇百分比 | `FAN_SPEED` (0x10) | 扩展 `gpu.fan`（非校准百分比，不入 `ActualPercent`） |

### 9.2 覆盖边界（如实声明）

- MAHM **只有 GPU 侧读数**，**不提供**：CPU 温度、CPU 频率、CPU 封装功耗、GPU 功耗。
  因此启用 Afterburner 后：CPU 四项仍走 ACPI 热区 + PDH（不变），`GpuSnapshot.PowerWatt` **恒为不可用**，
  扩展项「GPU 功耗限制」「GPU 降频温度阈值」不再提供（这些是 NVML 专有）。
- 风扇百分比是 Afterburner 的占空比，**不是校准后百分比**，按其语义不入 `FanReading.ActualPercent`。

### 9.3 配置步骤

1. **安装并运行 MSI Afterburner**（含 RivaTuner Statistics Server 组件），保持其**常驻**。
2. 在 Afterburner「设置 → 监控」页，勾选需要读取的 GPU 项（GPU 温度、核心频率、显存频率、
   GPU 利用率、显存占用、风扇转速等），使 Afterburner 开始轮询这些数据。
3. 装配时传入开关（见 §7 接入代码）：
   ```csharp
   var monitoring = MonitoringProviderFactory.CreateDefault(capabilities, preferAfterburner: true);
   ```
   未显式启用时（默认 `false`）保持 NVML 为 GPU 主来源，Afterburner 不接入。

### 9.4 兼容性与配置问题（风险清单）

| 风险 | 说明 | 本项目应对 |
|---|---|---|
| **本机当前未安装 Afterburner** | 2026-10-17 实测无安装目录、无进程、无卸载项（任务书 §4 的「已装」是早期记录） | 读取器返回「不可用」，界面显示原因，不崩溃、不伪造 |
| 闭源私有内存布局 | 结构体偏移随版本可能变化 | 读取器校验签名与条目大小，不符即降级「不可用」 |
| 需第三方常驻 | Afterburner 退出即断数据 | 仅作可选来源；默认 NVML 不依赖第三方 |
| 与设计定稿 §10 冲突 | 定稿要求接管 GPU 功耗/风扇、Afterburner 应关闭重叠自动应用 | 默认关闭；启用属用户显式选择 |
| GPU 功耗缺失 | MAHM 不暴露功耗 | `PowerWatt` 如实「不可用」 |

## 10. PawnIO EC 数据源接入（2026-10-17 追加）

> 对应叶哥「接入 PawnIO 检测与风扇功能」的要求。寄存器表来自 `Ms15M3EcRegisterMap`
> （msi-ec CONF_G2_10，固件白名单精确覆盖本机 15M3EMS1.105–.113，证据清单 §16）。

### 10.1 新增数据源与映射

| 数据源 | 寄存器 | 映射到 | 实测 |
|---|---|---|---|
| `PawnIoEcTemperatureSource` | 0x68 CPU 实时温度 | `CpuSnapshot.Temperature`（**排在热区兜底之前**） | 69 °C ✅ |
| `PawnIoEcTemperatureSource`（扩展） | 0x80 GPU 实时温度 | 扩展 `gpu.temperature.ec`（与 NVML 交叉核对） | 47 °C ✅（与 NVML 一致） |
| `PawnIoEcFanSource` | 0x71 / 0x89 风扇占空比 | `FanReading.ActualPercent`（硬件直报百分比） | CPU 18%、GPU 11% ✅ |

- **`FanReading.FromHardwarePercent`**（Core 新增加法工厂）：EC 寄存器表**不提供 RPM**，
  因此百分比走「硬件直接报告」语义进入 `ActualPercent`，RPM 槽位如实「不可用」并注明原因。
  界面「百分比(R)」显示模式由此正常显示实际转速；RPM 模式显示「不可用」属诚实行为。
- **CPU 温度不再用热区兜底**：EC 0x68 是真实 CPU 温度，精度优于 ACPI 热区；
  EC 不可用时自动回落热区（链内第一优先）。

### 10.2 前置条件（重要）

- **PawnIO 驱动**：`winget install namazso.PawnIO`（未安装时源返回精确原因）。
- **必须以管理员身份运行 MSI-Control**：PawnIO 设备句柄需要提权；非提权进程会得到
  「需要管理员权限运行」这一明确原因，此时 CPU 温度自动回落热区、风扇显示不可用。
- EC 固件版本出白名单（如未来升到 .114+）时寄存器表自动失效，通道拒绝工作。

### 10.3 风扇「控制」的边界（如实声明，不虚假开放）

- 本轮接入的是**读取**（占空比、温度）。**风扇写入控制仍处于安全闸门之后**：
  PawnIO 通道的写白名单恒为空集，任何 `WriteRegister` 在协议层之前被拒绝（有单测锁定）。
- 开放写入的前置条件（任务书 §16.1：能力必须达 `Verified`）：
  1. A3–A7 受控对照实验（切档 0xD4、场景 0xD2、负载差分 0x68/0x71、0x80/0x89、强冷 0x98 bit7，
     **需叶哥配合操作**）→ 寄存器语义升证据；
  2. 阶段 B 定位手写转速寄存器；
  3. 阶段 C `FanHardwareMs15M3Ec` 写路径 + `fan.curve`/`fan.pwm` 升 `Verified`。
- 在此之前，任何「已可控制风扇」的宣称都是虚假成功，本项目不做。

### 10.4 异常处理说明（实测验证）

| 异常 | 行为 | 实测 |
|---|---|---|
| EC 读时序超时（瞬时抖动） | 该读数本周期「不可用」，CPU 温度自动回落热区，下周期自恢复；**绝不沿用旧值** | ✅ 复现一次（0x68 等待 OBF 超时 50ms），降级路径正确 |
| PawnIO 驱动未安装 / 非管理员 | 通道创建失败原因缓存并上报，60 秒自动重试 | 设计 + 单测覆盖 |
| EC 固件出白名单 | 寄存器表失效，通道拒绝工作并说明 | 设计 + 单测覆盖 |
| Afterburner 未安装 | GPU 回落链自动落到 NVML，界面无感知 | 实测（本机未装 AB，NVML 正常） |
| 独显休眠 | 回落链立即采纳 Sleeping，不再尝试后备（避免唤醒独显） | 单测覆盖 |
| 全部 GPU 来源失败 | 合并各路径原因呈现，不伪造数值 | 单测覆盖 |
| 采样超时 / 数据过期 | `SnapshotStream.MarkStale`，有效读数转过期 | 沿用任务 02 机制 |
