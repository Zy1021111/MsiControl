═══ 三、你的职责 ═══

负责 MsiControl.Application、tests/MsiControl.Application.Tests，

（一）控制协调器
正常窗口、迷你窗口、托盘、快捷键与供电事件都向它发请求，流程为：

    用户操作 / 供电变化 / 启动恢复
                 ↓
        ControlCoordinator
                 ↓
    检查能力与条件 → 顺序应用设置 → 读取确认
                 ↓
        更新共享状态与逐项操作结果
                 ↓
          正常窗口 / 迷你窗口

协调器必须满足：
- 硬件写入**串行执行**，避免性能切换与风扇编辑互相覆盖。
- 合并尚未执行的过期请求，**尊重最新手动选择**。
- 每个设置**单独报告结果**。
- 出现部分失败时先读取当前状态，**不盲目宣称整组回滚成功**。
- 恢复启动设置前，检查设备、配置与当前供电状态。
- 长操作不阻塞 UI；每个操作有超时与明确结果。

（二）启动恢复策略
- 开机启动默认开启、可关闭。默认显示正常窗口。
- 恢复最近成功应用的性能与风扇配置。
- 恢复前校验设备、配置适用性与当前供电状态。
- **不自动切换显卡模式。**

（三）供电变化策略
- 拔电：记录原性能模式，自动切换节能。
- 插电：若拔电后**未**发生手动选择，恢复拔电前模式；
        若**已**发生手动选择，保留手动选择。
- **不自动切换显卡模式。**
- 启动恢复与供电变化**不得覆盖更新的手动选择**。

（四）退出行为
- 目标是保留最后成功应用的硬件状态。
- 固件持久执行的设置可以在进程退出后继续生效。
- 依赖持续软件控制的设置，**不能承诺在全部进程退出后维持**，要在界面上说明。
- 若实测必须保留控制进程，必须明确区分「退出界面、继续控制」与「停止全部进程」，
  并在停止全部进程前明确显示相关设置的实际退出行为。
- **不以隐藏进程冒充完全退出。**

（五）第三方工具共存
- 检测可识别的冲突来源（本机装有 Intel XTU 与 MSI Afterburner）。
- 显示设置被其他程序覆盖的状态。
- **不通过无休止重写争夺控制**；不修改或删除其配置；不自动停止或卸载它们。

（六）整合与验证（待 02–06 可用后进行）
- 睡眠唤醒、重启后的行为。
- 两种窗口状态一致性。
- 快捷键与托盘。
- 第三方工具实际冲突。
- 不等所有模块完成才第一次整合；先接可用的模块。

（七）资源测量与优化
分别测量并报告：正常窗口 / 迷你窗口 / 托盘待机 / 风扇编辑 / 校准过程。
记录内存（说明口径，如工作集与私有内存）、稳态 CPU、启动耗时、磁盘占用。
优化要求：单一共享采样、不重复初始化硬件、隐藏页面停止绘制、

═══ 七、已知编码陷阱（基线中已踩过，直接遵守）═══

- xunit v2 不提供隐式 using，测试文件必须显式写 using Xunit;。
- record 陷阱：可空位置参数传裸 null 会被解析到 record 自动生成的拷贝构造函数
  （参数为不可空引用类型），触发 CS8625。必须用命名参数，如 new(ActiveStage: null)。
- ControlResult 的整体状态由 ControlResult.From(...) 归并，不允许手工指定。
  归并规则：全失败→Failed；部分失败→PartiallySucceeded；有不支持→PartiallySucceeded；
  有 PendingRestart→PendingRestart；其余→Succeeded。
- ControlResult.Validate() 会检出「成功但无确认依据」与「不支持但未说明依据」，
  在测试中断言它为空。
- FanCurve.Validate 校验「给定顺序」；FanCurve.TryCreate 先按温度排序再校验。
- 单位换算只走 MsiControl.Core.Measurement。
