═══ 三、你的职责 ═══

负责 MsiControl.Fans，以及 src/MsiControl.Hardware.Msi/Devices/Ms15M3/Fan*.cs

1. 调查并验证 MS-15M3 的风扇接口
   确定：曲线读取路径、曲线格式（节点数量、温度是否可编辑、输出范围与步长）、

   - ReadAsync：读当前控制模式与设备上已生效的曲线。
   - ApplyCurveAsync(channel, curve)：写入指定通道曲线。
   - SetAutomaticAsync：切回固件自动策略。注意这不是 BIOS 出厂重置。
   - SetFullSpeedAsync(enabled)：强冷开关。

3. 曲线校验与应用流程（放在本模块，不放底层接口）
   - 用 FanCurve.TryCreate 构造曲线并展示所有校验错误。
   - 应用前用硬件实际报告的能力再做一次校验（节点上限、输出范围、温度可编辑性）。
   - 首次修改前读取并保存有效快照。
   - 只有**显式应用**才写入硬件。
   - 写入后必须读回确认；失败时重新读取实际状态并显示。

4. 状态区分
   界面必须能区分四件事：编辑中的配置 / 本地保存的配置 /
   最近成功应用的配置 / 当前读到的硬件状态。
   「恢复启动曲线」恢复到本次启动后首次写入前的快照，**不是** BIOS 出厂重置。

5. 每档性能模式独立双风扇曲线
   五档各自拥有独立 CPU/GPU 曲线。曲线由本模块提供校验与执行，
   配置存储由 02 负责，档位编排由 05/07 负责。接口不一致时先协商，不要各建一份。

6. 校准
   显示过程与结果、支持取消、保存有效 RPM 基准、完成或取消后恢复原策略并核对。
   校准只建立满速 RPM 基准，**不等于**建立输出百分比到 RPM 的完整精确映射。

7. 执行机制
   优先让固件执行曲线。
   若实测必须软件持续调速，必须实现：温度滞回、升降速节流、传感器超时处理、
   睡眠唤醒处理、异常退出保护。并明确说明该设置依赖控制进程存活。

═══ 七、已知编码陷阱（基线中已踩过，直接遵守）═══

- xunit v2 不提供隐式 using，测试文件必须显式写 using Xunit;。
- record 陷阱：可空位置参数传裸 null 会被解析到 record 自动生成的拷贝构造函数
  （参数为不可空引用类型），触发 CS8625。必须用命名参数。
- FanCurve.Validate 校验「给定顺序」；FanCurve.TryCreate 先按温度排序再校验，
  所以乱序输入会被接受。两者语义不同，不要混用。
- FanCurve.Interpolate 返回的是**曲线目标输出**，不是实际转速。
  实际转速受固件策略与硬件限制影响，两者不得互相替代。
- 限制类只能经工厂方法构造；单位换算只走 MsiControl.Core.Measurement。
