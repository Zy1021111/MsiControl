═══ 三、你的职责 ═══

负责 MsiControl.Graphics，以及
src/MsiControl.Hardware.Msi/Devices/Ms15M3/Graphics*.cs（文件归属见任务书 §15.1）。

1. 调查并验证能力
   确定本机是否支持核显 / 混合 / 独显直连三种模式，
   以及每种模式对应的真实写入路径与生效条件。
   能力判定结果写入 docs/hardware-evidence.md，并据此设置 CapabilityLevel。
   **按功能判断能力，不把「同系列机型支持」当作本机支持。**

2. 实现 IGraphicsHardware
   - ReadAsync：读当前实际模式、待生效模式与能力信息。
   - RequestModeAsync(mode)：请求切换。结果可能是 PendingRestart
     （已写入，需重启或 S5 关机再开机生效）。

3. 当前模式与待生效模式必须分开
   用 GraphicsHardwareState 的 Current 与 Pending 两个字段。
   界面显示待生效状态时**不得覆盖实际状态**（任务书 §9.1）。
   明确告知用户是需要普通重启还是 S5 关机再开机，以实际情况为准，不要笼统写「需重启」。

4. 切换前的条件检查
   - 与性能模式独立保存。
   - **不在启动时自动切换显卡模式。**
   - **不在供电变化（拔电/插电）时自动切换显卡模式。**
   - 支持「稍后生效」，**不自动重启设备**。
   - 切换生效后重新读取确认。

5. 外接屏约束（用户的实际场景）
   用户使用 DP 转雷电连接外接显示器。切换前必须确认：
   - 雷电 / USB-C 到显示器的**实际连接路径**（走核显还是独显）；
   - 外接显示器是否依赖独显输出；
   - 目标模式是否会使外接屏断开；
   - 是否存在接口数量限制。
   **不能仅根据线缆名称推断显示拓扑。**
   实现上调用 GraphicsHardwareState.WouldDisconnectExternalDisplay(target)：
   返回 null 表示拓扑未知，此时**不得按「无风险」处理**，应在界面上给出明确警告。

6. 严禁的替代做法（任务书 §9.3）
   - 不用设备管理器禁用独显冒充核显模式。
   - 不用应用 GPU 偏好（如 NVIDIA 控制面板的显卡首选项）冒充 MUX 切换。
   - 不混淆 MUX 与 Advanced Optimus。

═══ 七、已知编码陷阱（基线中已踩过，直接遵守）═══

- xunit v2 不提供隐式 using，测试文件必须显式写 using Xunit;。
- record 陷阱：可空位置参数传裸 null 会被解析到 record 自动生成的拷贝构造函数
  （参数为不可空引用类型），触发 CS8625。必须用命名参数，如 new(ActiveStage: null)。
- GraphicsHardwareState 的 Current 与 Pending 是不同字段，
  HasPendingChange 只在 Pending 有值且不等于 Current 时为真。
- WouldDisconnectExternalDisplay 返回 bool?（三态）：true / false / null(拓扑未知)。
  不要把它当 bool 用。
- Current / Pending 用可空枚举，未适配时保持 null，不要用默认值冒充已知。
- 单位换算只走 MsiControl.Core.Measurement。
