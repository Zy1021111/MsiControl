## 1. 定位与边界

`MsiControl.Core` 是**纯契约层**：

| 包含 | 不包含 |
|---|---|
| 数据模型、枚举、状态语义 | 任何硬件访问实现 |
| 硬件访问接口定义 | WMI / ACPI / EC 调用 |
| 能力等级制度 | 界面代码 |
| 单位换算的唯一入口 | 配置持久化 |
| 逐项操作结果类型 | 任何 `Set_*` 行为 |

因此本工程**无任何外部依赖**，也不引用 `System.Management`。

## 3. 核心约定（违反即评审不通过）

### 3.1 成功必须有确认依据

```csharp
// 正确：说明凭什么认为生效
SettingResult.Succeeded("cpu.longterm", "60 W", "60 W", confirmationBasis: "写入后读回 60 W");

// 错误：调用没抛异常就报成功
new SettingResult("cpu.longterm", "60 W", null, OperationStatus.Succeeded);
```

`ControlResult.Validate()` 会检出「成功但无确认依据」与「不支持但未说明依据」两类违规。

### 3.2 原生上限不得用数字表达

```csharp
PowerLimit.Native            // 正确
PowerLimit.Custom(60m)       // 正确
PowerLimit.Custom(0m)        // 抛异常
PowerLimit.Custom(-1m)       // 抛异常
new PowerLimit { Watts = 9999m }  // 编译不过：构造函数私有
```

限制类只能经工厂方法构造，`TryCustom` 会拦截 0、负数与超过 `MaxCustomWatts` 的数值。

### 3.3 数据过期不得沿用旧值

```csharp
SensorReading.Stale(60.05, Units.Celsius, "MSI_ACPI", lastSampledAt)  // IsUsable == false
snapshot.MarkStale("采样超时")                                        // 批量标记
snapshot.IsFreshAt(DateTimeOffset.Now, TimeSpan.FromSeconds(5))        // 是否仍在有效期内
```

`IsUsable` 仅在 `Status == Valid` 且 `Value.HasValue` 时为真。

**v1.2 起 `MarkStale` 的精确语义**（这是本轮修正的一处真实缺陷）：

- 只把**原本有效**的读数转为过期；`Unavailable` 与 `Sleeping` **保持原状**。
- 覆盖 CPU、GPU、**双风扇**、**整机功耗**与**扩展传感器**。
- 幂等：重复调用不会进一步改变已过期的读数。

```csharp
SensorReading.Unavailable(...).AsStaleIfValid("超时").Status  // 仍为 Unavailable，未被改写
```

> 为什么重要：把「读不到」和「独显休眠」改写成「数据过期」，
> 会让界面无法区分**设备休眠**与**接口故障**（任务书 §6.4 要求四态分列）。

### 3.4 实际转速与曲线目标必须分开

```csharp
FanReading.Valid(rpm: 3900, source: "MSI_ACPI", sampledAt: now,
                 actualPercent: 78,    // 由校准基准推导
                 targetPercent: 60);   // 曲线输出
```

未完成校准（`HasCalibration == false`）时 `ActualPercent` 为 `null`，界面必须回落显示 RPM。

### 3.5 能力未达 Verified 不得开放写入

```csharp
capabilities.AllowsWrite(CapabilityKeys.FanCurve)  // 仅在 Verified 时为 true
capabilities.LevelOf("未登记的键")                  // 一律 Unknown → 禁用
```

未登记的能力默认 `Unknown`（禁用），**不是默认可用**。

### 3.6 整机功耗不得替代

```csharp
SystemPowerReading.Unavailable("本机无适配器侧读数")   // 正确
// 错误：把 Cpu.PackagePowerWatt + Gpu.PowerWatt 当成整机功耗
```

口径由 `PowerSourceKind` 表达，三者（`BatterySide` / `AdapterInput` / `WallSocket`）不可相加。

### 3.7 能力基线用法（`MsiControl.Hardware.Msi.Capabilities`）

任务书 §16.1 的能力等级映射已**落成代码**，模块不再各自硬编码等级：

```csharp
using MsiControl.Hardware.Msi.Capabilities;

var caps = CapabilityBaseline.ForDevice(deviceIdentity);   // 非 MS-15M3 → 空集合（全禁用）

caps.AllowsWrite(CapabilityKeys.FanCurve);          // false —— Detected 仅可读
caps.AllowsWrite(CapabilityKeys.ThermalFallback);   // true  —— 唯一 Verified（只读用途）
caps.LevelOf(CapabilityKeys.GraphicsMode);          // Unknown —— 一律禁用
```

MS-15M3 当前等级分布（依据 `docs/hardware-evidence.md`）：

| 等级 | 能力键 |
|---|---|
| `Verified` | `thermal.fallback`（通用 ACPI 热区，唯一已确证项） |
| `Detected` | `fan.curve`、`thermal.read`、`cpu.power`、`gpu.power`、`power.range`、`power.battery`、`ec.access`、`firmware.scenario` |
| `Unknown` | `fan.fullspeed`、`fan.calibration`、`cpu.turbo`、`gpu.eco`、`graphics.mode`、`power.system` |
| `Unsupported` | 无（`MSI_CPU` 等 5 个类是**被排除的硬件类**，不是能力键） |

> 升级规则：等级只能由实测证据推动（约定 §1.2）。**仅凭方法名存在不得升级。**
> 升级时同时修改 `Ms15M3Capabilities` 并同步 `docs/hardware-evidence.md`。

### 3.8 构造期强制不变量（v1.2 新增）

以下类型的**构造函数是私有的**，只能经工厂方法创建；非法组合在对象诞生前即被拒绝：

| 类型 | 强制的不变量 |
|---|---|
| `SensorReading` | `Valid` 必须有值且有采样时刻；`Sleeping`/`Unavailable` **不得携带数值**；单位与来源非空 |
| `CapabilityStatus` | `Verified`/`Detected` 必须有证据；`Unsupported` 必须有依据；能力键非空 |
| `FanReading` | RPM 不得为负；两个百分比字段必须落在 0–100 |
| `PowerLimit` / `CpuTurboLimit` | 瓦数/频率必须为正的有限值；原生上限只能用 `Native` |

**代价（须知）**：`SensorReading` 因此**不支持 `with` 表达式**——
允许 `with` 等于重新打开任意字段改写，与不变量强制冲突。
需要转换时请用现成方法：`AsStale`、`AsStaleIfValid`、`FanReading.WithRpm`。

### 3.9 组合校验必须显式调用（v1.2 新增）

`PowerLimit` 等只保证**单个值**合法，字段之间的组合关系由各类型自己的 `Validate()` 负责：

```csharp
// 短时上限低于持续上限、曲线绑到错误通道 —— 都会被检出
var problems = performanceSettings.Validate();
var resultProblems = controlResult.Validate();
var capabilityGaps = capabilities.MissingKeys();   // 基线与 CapabilityKeys 脱节
```

**写操作前必须检查 `Validate()` 返回为空**；非空时先修正配置，不要直接下发硬件。

### 3.10 设备标识必须双向有效（v1.2 新增）

```csharp
DeviceIdentity.Unknown.IsSameBoardAs(DeviceIdentity.Unknown)  // false —— 未识别 ≠ 同机型
```

`IsSameBoardAs` **要求双方都已标识**（`IsIdentified`：主板码非空且不等于 `"Unknown"`）。
配置导入前须同时检查 `IsIdentified` 与 `IsSameBoardAs`。

> 为什么重要：若放任两台都没读出主板码的设备判为同机型，
> 跨机型配置会被错误放行导入，违反任务书 §2.2。

### 3.11 只读发现与只读调用通道（v1.3 新增）

任务 01 只交付**只读**硬件访问，供 03 监控与阶段 A 证据采集使用；**不开放任何 `Set_*`**。

```csharp
using MsiControl.Hardware.Msi.Discovery;
using MsiControl.Hardware.Msi.Transport;

// 1) 只读发现：类/实例/方法元数据 + 排除类 + 热区
IHardwareDiscovery discovery = new WmiHardwareDiscovery();
HardwareDiscoveryReport report = await discovery.ScanAsync(ct);
report.IsMsiAcpiAvailable;                 // MSI_ACPI 是否可用
report.MsiAcpi.Methods[0].WmiMethodId;     // 命令字（从 MOF 读取，非硬编码）
report.ThermalZones[0].CurrentCelsius;     // 已由 Measurement 换算为 °C

// 2) 只读调用：仅允许登记在 MsiAcpiMethodNames.Read 中的方法
IMsiAcpiTransport transport = new WmiMsiAcpiTransport();
var r = await transport.InvokeReadAsync("Get_Temperature", null, ct);
await transport.InvokeReadAsync("Set_Fan", null, ct);   // → Blocked：写入通道未开放
```

**两条硬约束（实机教训）：**

1. **`Data` 参数在 MOF 中声明为 CIM `Object`（VARIANT），不是字节数组。**
   通道因此按 `object` 原样透传、不断言类型；具体编码**尚未验证**。
2. **本机 `OutParameters` 不含 `ReturnValue`** → 无法判定固件是否接受调用。
   此时 `MsiAcpiInvocationResult.Accepted` 为 `null`（未知），
   **调用方必须读回确认，不得默认成功**。

> `WmiObjectAccess` 存在的唯一原因：`ManagementBaseObject` / `PropertyDataCollection` 的
> 字符串索引器在键不存在时**抛 `ManagementException`（`0x80041002`）而不是返回 `null`**。
> 首版 `Discovery` 曾因此把存在的 `MSI_ACPI` 误报为「找不到」。一律按名遍历、吞集合级异常。

## 4. 状态语义速查

### `ReadingStatus`

| 值 | 界面表现 |
|---|---|
| `Valid` | 显示数值 |
| `Sleeping` | 显示「休眠」 |
| `Unavailable` | 显示「不可用」 |
| `Stale` | 显示数值但**标注为过期** |

### `OperationStatus`

| 值 | 含义 |
|---|---|
| `Succeeded` | 已确认生效 |
| `PartiallySucceeded` | 部分成功。**不得宣称整组回滚成功** |
| `Failed` | 失败 |
| `PendingRestart` | 已写入，需重启或 S5 关机再开机生效 |
| `Unsupported` | 本机不支持，必须附依据 |

### `CapabilityLevel`

| 值 | 允许行为 |
|---|---|
| `Verified` | 可开放读写 |
| `Detected` | 仅只读展示 |
| `Unknown` | 一律禁用 |
| `Unsupported` | 显式禁用 |

> **v1.2 起等级与依据在构造期绑定**：`Verified` / `Detected` 无证据、
> `Unsupported` 无依据的对象**无法被构造**。因此不存在「声称可用却拿不出证据」的实例。
> 界面展示禁用原因请用 `CapabilityStatus.DescribeUnavailable()`。

## 5. 各任务接入指引

> **能力等级一律取自 `CapabilityBaseline.ForDevice(deviceIdentity)`，不要自行硬编码等级。**
> 未适配机型该入口返回空集合，即全部能力 `Unknown` / 禁用——这是默认安全方向。

### 任务 02 桌面框架

- 订阅单一采样结果，渲染 `MonitoringSnapshot`。
- 用 `CapabilityLevel` 控制各入口的启用/禁用与提示文案。
- 配置持久化时记录 `DeviceIdentity`；导入时须**同时**检查 `IsIdentified` 与 `IsSameBoardAs`
  —— 未识别机型一律拒绝导入，避免跨机型配置被错误放行（见 §3.10）。

### 任务 03 实时监控

- 实现 `IMonitoringProvider`。
- 温度换算**必须**调 `Measurement.DeciKelvinToCelsius`，不要自行 `/10 - 273.15`。
- 独显不可读时返回 `GpuSnapshot.Sleeping(...)`，不要返回 `Unavailable`。
- 采样超时调 `MonitoringSnapshot.MarkStale(...)`。
- 兜底温度源可直接用 `WmiHardwareDiscovery` 读取通用 ACPI 热区；
  精确 CPU/GPU 温度仍须走 `MSI_ACPI`，其 `Data` 协议**尚未验证**（见 §3.11）。

### 任务 04 风扇控制

- 实现 `IFanHardware`；曲线构造用 `FanCurve.TryCreate` 并展示 `errors`。
- 应用前须用硬件报告的能力（`MaxCurveNodes` 等由实现方在 `FanHardwareState` 中补充）再校验一次。
- 结果用 `ControlResult.From(...)` 归并，不要手工指定整体状态。

### 任务 05 性能与功耗

- 实现 `IPerformanceHardware`。
- 默认配置取自 `PerformanceProfileCatalog`，不要另建一份数值表。
- 目标不受支持时填 `GpuEcoFallback`，**不要静默改数**。

### 任务 06 显卡切换

- 实现 `IGraphicsHardware`；待生效用 `Pending`，不要覆盖 `Current`。
- 切换前调 `WouldDisconnectExternalDisplay`；返回 `null` 表示拓扑未知，**不得按无风险处理**。

### 任务 07 自动策略与整合

- 协调器负责串行写入与请求合并；`ControlResult` 由 Core 归并，协调器只做调度。
- 部分失败时先读取实际状态，再决定是否回滚。

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| 无硬件实现 | 两个工程按设计均不含任何 `Set_*` 行为，四个接口均无实现类 |
| 能力基线不耦合契约层 | MS-15M3 的具体能力映射在 `MsiControl.Hardware.Msi.Capabilities`，`MsiControl.Core` 只提供键名与等级类型。**已落码**，不再是文档表格 |
| 曲线节点上限未建模 | 由 `FanHardwareState` 的实现方提供，Core 只做通用范围校验 |
| 待生效语义仅覆盖重启 | `PendingRestart` 不表达「不重启但有过渡期」的情形 |
| 写入通道未开放 | `Transport` 只接受 `MsiAcpiMethodNames.Read` 中的方法，`Set_*` 一律 `Blocked`。开放条件：对应能力达 `Verified`，且由 04/05/06 提出并公告（任务书 §15.1） |
| `Data` 编码未验证 | 实机确认 `Data` 为 CIM `Object`（VARIANT），但具体编码与语义未知。须由阶段 A 的受控只读 `Get_*` 调用确立（`docs/hardware-evidence.md` §8 Step 3） |
| 无法判定调用是否被接受 | 本机 `OutParameters` 不含 `ReturnValue`，`Accepted` 为 `null`。**必须读回确认** |
| MOF 注册来源仍未定位 | 阶段 A 首要项（任务书 §4.1 A1）。`Discovery` 只读出了类/实例/方法，**不回答** MOF 由谁注册 |
| 测试工程未登记于任务书 | `tests/MsiControl.Hardware.Msi.Tests` 系新增，已登记于 `docs/接口与工程约定.md` §4，待整合负责人同步任务书 §14/§15.1 |
| `SensorReading` 不支持 `with` | v1.2 起构造函数私有以强制不变量，代价是失去 `with` 表达式。转换请用 `AsStale` / `AsStaleIfValid` / `FanReading.WithRpm` |
| `CapabilityKeys` 与能力基线的校验点分散 | 基线侧由 `CapabilityBaselineTests` 断言全覆盖，契约侧由 `DeviceCapabilities.MissingKeys()` 提供自检。两处分属不同工程，建议整合时统一由 07 收口 |
| `Hardware.Msi` 为 `net8.0-windows` | 因 `System.Management` 平台限制。消费方（含测试）须同为 `net8.0-windows`；`Core` 保持 `net8.0` |

## 8. 接口变更流程

1. 需要变更共享接口的任务，先提出变更请求，**不要直接改 `src/MsiControl.Core`**。
2. 由任务 01 评估影响面（涉及哪些模块的编译）。
3. 变更落地后更新本文件与 `docs/接口与工程约定.md`。
4. 同步通知 02—07。
