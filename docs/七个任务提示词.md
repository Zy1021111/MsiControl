版本：v1.1（配合任务书 v1.2）
用法：在项目目录 `F:\Codex programs\msi控制台` 下新建 7 个独立对话，每个对话粘贴「共同要求」+ 对应任务正文。

## 共同要求（粘贴到每个对话开头）

```text
开发开源 Windows 工具 MSI-Control，主要参考 G-Helper 的轻量、紧凑设计。
工作目录 F:\Codex programs\msi控制台。

【先读，再动手】
开工前必须依次读完：
- MSI-Control-开发总流程与任务书.md（尤其 §0 修订说明、§4.1 已知约束与风险、§15.1 文件归属矩阵）
- docs/hardware-evidence.md（本机能力证据清单）
- docs/接口与工程约定.md（能力等级制度与单位口径）
- docs/接口说明.md（任务 01 已交付的共享接口）

【目标设备】
MSI Vector 16 HX AI A2XWHG / MS-15M3（国行名「泰坦16 AI 2025」），
CPU Intel Core Ultra 9 275HX，GPU RTX 5070 Ti Laptop，BIOS E15M3IMS.117。

【硬性纪律】
1. 仅修改本任务负责模块，保留其他任务的改动。文件归属见任务书 §15.1。
2. 共享接口由「01 基础接口」统一维护，需要变更先提出，不自行改动 src/MsiControl.Core。
3. docs/design.md 已批准冻结，不得修改。
4. 不猜测寄存器地址、方法参数或数值含义。参数含义必须来自源码、接口定义或实机证据。
5. 不把「WMI 类存在」「方法名存在」当作「功能可用」的证据。
6. 能力未达到 CapabilityLevel.Verified 前，界面不得开放写入。
7. 不把模拟数据当真实读数。模拟数据只能由显式开发开关启用，并始终标注「模拟」。
8. 不显示虚假成功。Succeeded 必须有可追溯的确认依据；无法读回的操作要写明确认方式和限制。
9. 不自动刷固件、不关闭安全保护、不重启电脑、不修改 Intel XTU / MSI Afterburner 的配置。
10. 涉及风扇全速、持续负载、显示中断或重启的测试，先说明步骤和恢复入口，等用户配合，不要擅自执行。

【必须排除的噪声类】
root\WMI 中的 MSiSCSI_*（Microsoft iSCSI）、MSIde*（Microsoft IDE）、
ISR_MSI（= Message Signaled Interrupts，非品牌）与 MSI 笔记本无关，不得作为能力证据。
另外 MSI_CPU / MSI_Power / MSI_VGA / MSI_Master_Battery / MSI_Slave_Battery
已确认返回 WBEM_E_NOT_SUPPORTED（只有类定义无实例），禁止在代码中引用。

【交付要求】
- 交付时必须附上真实的 `dotnet build` 与 `dotnet test` 输出，不得声称「应该可以编译」。
- 新发现的能力或限制，追加到 docs/hardware-evidence.md，标注证据等级，不删除他人条目。
- 无法实现的要求，给出证据、具体限制和可行替代方案，不得用虚假成功状态满足界面要求。
```

## 01 基础接口

负责 `MsiControl.Core`。先将本项目已批准的设计整理到 `docs/design.md`（**注意：该文件已定稿冻结，只读引用，不要改写正文**），建立共享模型、能力状态、监控快照、五档性能配置、风扇曲线、功耗限制、CPU 睿频上限、显卡模式和逐项操作结果。定义各模块接口与单位，明确请求状态和实际状态。制定模块边界及工程约定，提供可编译基础工程和接口说明。不要实现真实硬件写入。

> 状态：**已完成首版**。工程在 `src/MsiControl.Core`，说明见 `docs/接口说明.md`。
> 后续任务如发现接口不足，请向 01 提出变更，不要自行修改 Core。

## 02 桌面框架

负责 `MsiControl.Desktop` 和 `MsiControl.Persistence`。基于共享接口实现轻量 WinForms 桌面壳、正常窗口、迷你窗口、系统明暗主题、托盘、单实例、快捷键和本地配置。默认正常窗口、开机启动、关闭到托盘；迷你窗口不置顶、不含强冷按钮。两种窗口共用数据与控制核心。完整功能入口清晰，未适配功能明确禁用。先参考 G-Helper 的实际源码和依赖，再确定细节。

## 03 实时监控

负责 `MsiControl.Monitoring`。实现每秒一次的共享采样：CPU/GPU 温度、统一频率、功耗、双风扇 RPM/校准后百分比、扩展传感器、来源和更新时间。独显休眠显示“休眠”，读取失败显示“不可用”，过期数据明确标注。独立调查整机功耗来源，不能用 CPU+GPU 功耗冒充。避免持续唤醒独显，避免周期性启动命令行进程。记录本机传感器覆盖与资源占用。

> 注意：`MSAcpi_ThermalZoneTemperature` 单位为**十分之一开尔文**，且本机仅 1 个热区，只能作兜底源。
> 换算统一使用 `MsiControl.Core` 中的 `Measurement` 类型，不要自行换算。

## 04 风扇控制

负责 `MsiControl.Fans` 及 `Hardware.Msi` 中独立的风扇适配文件。调查 MSI、G-Helper、NBFC 等相关实现，验证 MS-15M3 风扇接口。实现 CPU/GPU 曲线读取、校验、应用、读回、快照恢复、自动模式、强冷和校准。每档性能模式拥有独立双风扇曲线。曲线节点和输出范围服从硬件能力。优先固件执行；必须软件持续调速时明确生命周期和故障处理。不要修改其他硬件适配文件或擅自执行全速校准测试。

> 候选接口：`Get_Fan` / `Set_Fan`（证据等级：线索，未验证）。
> 强冷接口尚未定位，需自行调查，不得先假设存在。

## 05 性能与功耗

负责 `MsiControl.Performance` 及独立的 MSI 性能适配文件。调查并实现五档可编辑配置：节能 CPU 10W / GPU 20W、安静 50W / 80W、平衡 60W / 90W、高性能和狂暴恢复原生上限。每档支持 CPU 持续/短时功耗、CPU 睿频上限、GPU 功耗及双风扇策略关联。CPU 默认严格限制；GPU 20W 不支持时提供明确标注的兼容节能策略。狂暴不自动强冷。检测 XTU/Afterburner 覆盖，不无限重写争抢控制，不擅自修改它们的配置。

> 候选接口：`Get_Power` / `Set_Power`、`Get_Range` / `Set_Range`（证据等级：线索）。
> 「原生上限」必须用 `LimitMode.Native` 表达，禁止用 0 或极大数字代表无限。

## 06 显卡切换

负责 `MsiControl.Graphics` 及独立的 MSI 显卡适配文件。调查并验证核显、混合、独显直连能力，处理当前/待生效模式、切换条件和读回。用户使用 DP 转雷电外接屏，需要确认实际显示拓扑。不能以设备管理器禁用显卡或应用 GPU 偏好冒充模式切换。不自动重启，不在启动或供电变化时自动切换显卡。实际切换和重启测试先说明步骤，等待用户配合。

> 当前显卡模式能力为 `Unknown`，**尚未定位任何候选接口**，需从零调查。

## 07 自动策略与整合

负责 `MsiControl.Application`、集成验证和资源优化。先依据共享接口实现硬件写入协调、请求优先级、超时、部分失败、启动恢复与供电策略。拔电自动节能；插电恢复拔电前模式，但拔电后手动选过模式则保留手动选择。退出尽可能保留实际硬件状态，明确持续软件控制的限制。待其他模块完成后整合，验证睡眠唤醒、窗口状态、第三方工具冲突。测量正常、迷你、托盘状态的内存、CPU、启动和磁盘占用；不要重写其他模块来规避接口问题。

> 你同时是**整合负责人**，负责维护 `MSI-Control.sln` 与 `Directory.Build.props`（任务书 §15.1）。
