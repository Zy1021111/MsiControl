# 风扇恢复能力实测报告（任务 04）

版本：v1.0
日期：2026-10-16
对应：任务 04 提示词 §六「交付『恢复能力实测报告』：首次写入前快照、应用后读回、恢复后读回，
以及睡眠/重启后的行为。恢复能力必须实机验证，不预先保证一定成功。」

---

## 0. 一句话结论

**本机目前无法完成「写入 → 读回 → 恢复」的实机验证**，原因是风扇写入被能力门控关闭
（`fan.curve` = `Detected`，未达 `Verified`；写入载荷编码无证据）。因此本报告**不声称
恢复能力已实机验证**，而是如实区分「已确证」与「待验证」，并给出**需要用户配合**才能
完成的实验步骤。恢复能力**不预先保证一定成功**（任务书 §7.6）。

---

## 1. 已确证的部分（只读实测，来源 evidence §13）

| 项目 | 结论 |
|---|---|
| `Data` 参数形态 | 内嵌 CIM 实例 `root\WMI:Package`（属性 `Bytes`，`UInt8[]`） |
| `Get_Fan` 读取通道 | 可达；输入恰好 16 字节，返回 32 字节原始缓冲区 |
| 字段语义 | **未确证**；代码层拒绝解码 |
| 写入通道 | 关闭（两道闸门：能力未达 `Verified` + 载荷编码无证据） |

**因此**：`ReadAsync` 只返回「未知」状态，`ApplyCurveAsync` / `SetAutomaticAsync` /
`SetFullSpeedAsync` 一律 `Unsupported` 并给出依据，`ControlResult.Validate()` 为 0 个问题
（无「无依据的成功」）。这是诚实的行为，不是缺陷。

---

## 2. 恢复机制的代码层实现（已就绪，待硬件能力解锁后即可实机验证）

| 环节 | 实现 | 位置 |
|---|---|---|
| 首次写入前快照 | `FanBootSnapshotStore`：只捕获「可信」读取、已捕获后不覆盖、进程内保存 | `src/MsiControl.Fans/FanBootSnapshot.cs` |
| 恢复启动曲线 | `FanApplicationService.RestoreBootSnapshotAsync`：先校验快照仍满足当前硬件约束，再逐通道下发并读回核对 | `FanApplicationService.cs` |
| 取消后的核对 | 写入后被取消仍完成读回（带 3 秒上限）再抛出取消异常 | `FanApplicationService.cs` |
| 强冷进入/退出核对 | 进入前记录状态，退出后与进入前核对，不一致则提示手动恢复 | `FanApplicationService.cs` |
| 校准完成/取消恢复 | `FanCalibrationService.FinishAsync`：无论完成或取消都退出满速并核对 | `FanCalibrationService.cs` |

「恢复启动曲线」在语义上是「恢复到本次启动后首次写入前的快照」，**不是** BIOS 出厂重置；
该语义已写入 `FanBootSnapshotStore.RestoreSemanticsNotice` 并在界面文案中始终附带。

## 3. 待验证项（需要用户配合，本任务不擅自执行）

### 3.1 首次写入前快照 / 应用后读回 / 恢复后读回

**前置**：`fan.curve` 升到 `Verified`（需 §3.4 的协议证据），或取得可援引的
`Set_Fan` 载荷依据并完成受控写入验证。

**实验步骤**（届时由用户配合安排，本任务不会自行执行）：

1. 记录当前 `Get_Fan` 的 32 字节原始值（作为「写入前快照」的原始形态）。
2. 下发一条曲线（写入载荷需先取得协议依据）。
3. 立即读回 `Get_Fan`，核对返回是否与请求一致。
4. 触发「恢复启动曲线」，再读回，核对是否回到步骤 1 的原始值。
5. 每步记录原始返回与时间戳，作为升级 `fan.curve` 的证据。

### 3.2 睡眠 / 重启后的行为

- **睡眠唤醒**：唤醒后重新读 `Get_Fan`，判断固件是否保留自定义曲线、是否回落到自动策略。
- **重启（S5 关机再开机）**：判断曲线是否持久化在固件中。
- 仅当上述行为被观测后，才能决定「启动恢复」应恢复到什么（快照 / 固件当前态 / 自动策略）。

### 3.3 强冷与校准

- 强冷接口未定位（`fan.fullspeed` = `Unknown`），在定位前不做任何强冷/校准测试
  （提示词 §四.9）。
- 校准必须同时满足：用户同意（`FanCalibrationPlan.UserAcknowledgedFullSpeed`）、
  `fan.calibration` 与 `fan.fullspeed` 均达 `Verified`、已取得首次写入前快照。

### 3.4 字段语义的解码实验

32 字节缓冲区的字段含义，需要通过**受控对照**才能核证：

1. 在安静档与狂暴档之间切换（用户操作，或用已确证的固件场景接口），同时连续采样
   `Get_Fan`。
2. 观察哪些字节随档位稳定变化，哪些保持不变。
3. 取得「字段 ↔ 物理量」的对应关系后，再谈解码与写入。

## 4. 恢复能力的诚实声明

- 当前**不能**声称「恢复一定成功」；代码层已实现恢复机制，但**尚未在真实硬件上验证**。
- 在能力门控解锁并完成 §3 实验之前，界面必须对「恢复启动曲线」「强冷」「校准」保持
  **禁用 + 原因说明**，不得用「恢复成功」的假状态满足界面（任务书 §1 原则 6）。
